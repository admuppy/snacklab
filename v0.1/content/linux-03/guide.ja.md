# テキスト処理パイプライン

Linux 運用の半分は **ログを読むこと** です。grep・awk・sed の 3 つのツールをパイプでつなげば、数十万行のログから数秒で答えを引き出せます。

実習環境には Web サーバーのアクセスログ 2,000 行が用意されています。まず見た目を確認しましょう。

先頭 5 行を見る:

```
head -5 /var/log/lab/access.log
```

- `head -5 <ファイル>` — ファイルの先頭 5 行だけを表示する(`-n 5` と同じ)。

全体の行数を確認:

```
wc -l /var/log/lab/access.log
```

- `wc -l <ファイル>` — 行数を数える(word count の行オプション)。`-w` は単語数、`-c` はバイト数。

1 行の構造(空白区切りのフィールド番号):

| フィールド | 内容 | 例 |
|---|---|---|
| $1 | クライアント IP | `192.168.14.23` |
| $6~$8 | リクエスト(`"METHOD path HTTP/1.1"`) | `"GET /api/users HTTP/1.1"` |
| $9 | ステータスコード | `200` |
| $10 | レスポンスのバイト数 | `1532` |

## grep でエラーを探す

grep はパターンに合う **行を選び出す** ツールです。サーバーエラー(5xx)を探してみましょう。単に `grep 500` とするとバイト数が 500 の行も引っかかります — **ステータスコードの位置だけ** に一致させる必要があります。

```
grep -E '" 5[0-9]{2} ' /var/log/lab/access.log | head
```

- `grep -E` — 拡張正規表現。`5[0-9]{2}` は 5 で始まる 3 桁の数字。
- `'" 5[0-9]{2} '` — 引用符と空白で前後を囲み、ステータスコードの位置だけに一致させる。シェルが解釈しないよう全体をシングルクォートで囲んでいる。

`"` の後の空白に続く 5xx だけに一致するよう、前後の文脈を入れたのがポイントです。`-c` は一致した行数だけを出力します。

課題: 5xx エラーの行数を `~/work/err5xx.count` に保存してください。

5xx の行数を保存:

```
grep -Ec '" 5[0-9]{2} ' /var/log/lab/access.log > ~/work/err5xx.count
```

- `-c` — 一致した行の代わりに **行数** だけを出力する。`-E` と合わせて `-Ec`。
- `> ~/work/err5xx.count` — その数をファイルに保存する。

保存した値の確認:

```
cat ~/work/err5xx.count
```

- `cat` — ファイルの内容を表示して、保存された数を確認する。

保存したら **[チェック]** してください。

## awk でフィールドの抽出と集計

awk は行を **フィールドに分割して** 扱うツールです。`$1` が最初のフィールド(IP)です。

```
awk '{print $1}' /var/log/lab/access.log | head
```

- `awk '{print $1}'` — 各行を空白区切りのフィールドに分け、最初のフィールド(IP)だけを表示する。`{ }` の中が行ごとに実行される動作。

ここに定番の集計パイプライン `sort | uniq -c | sort -rn` を付けると頻度表になります。

```
awk '{print $1}' /var/log/lab/access.log | sort | uniq -c | sort -rn
```

- `sort` — 同じ IP 同士が隣り合うように並べ替え、`uniq -c` — 連続する同じ行を 1 つにまとめ、件数を前に付ける。
- `sort -rn` — 数値として(`-n`)降順(`-r`)に並べ替え → 多く出た IP が一番上。

> `uniq -c` は **隣り合った** 重複しか数えないので、必ず `sort` を先に置く必要があります。

課題: リクエストが最も多い IP を **1 つだけ**(IP の文字列だけ、件数は除く)`~/work/top-ip.txt` に保存してください。`head -1` で 1 行目を取り出し、awk で IP のフィールドだけをもう一度抽出すれば OK です。

```
awk '{print $1}' /var/log/lab/access.log | sort | uniq -c | sort -rn | head -1 | awk '{print $2}' > ~/work/top-ip.txt
```

- `head -1` — 1 位の行(`  123 1.2.3.4`)だけを残す。
- `awk '{print $2}'` — その行の 2 番目のフィールド(IP)だけを取り出して `>` で保存。

保存したら **[チェック]** してください。

## sed でストリーム編集

このログを外部に共有する必要がありますが、クライアント IP は個人情報なので **マスキング** が必要です。sed の置換(`s/パターン/置換/`)で解決します。

正規表現で行頭の IPv4 を捕まえます。`-E`(拡張正規表現)を使えば `{1,3}` の量指定子をそのまま使えます。

```
sed -E 's/^[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}/REDACTED/' /var/log/lab/access.log | head -3
```

- `sed -E 's/パターン/置換/'` — 行ごとにパターンに最初に一致した部分を置換して出力する(元のファイルは変わらない)。
- `^` — 行頭、`[0-9]{1,3}` — 1〜3 桁の数字、`\.` — ドット文字そのもの。合わせて行頭の IPv4 アドレス。

課題: ログ全体の IP を `REDACTED` に置換したコピーを `~/work/access-redacted.log` に保存してください。行数は元と同じでなければなりません(削除ではなく置換)。

置換したコピーを保存:

```
sed -E 's/^[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}/REDACTED/' /var/log/lab/access.log > ~/work/access-redacted.log
```

- 同じ置換をファイル全体に適用し、結果を新しいファイルに保存する。元ファイルを直接直すなら `-i` を使うが、ここではコピーを作る。

置換された行数の確認:

```
grep -c REDACTED ~/work/access-redacted.log
```

- `REDACTED` を含む行の数を数える。`wc -l` の結果(元の行数)と同じになるはず。

保存したら **[チェック]** してください。

## パイプラインの総まとめ

最後は実戦的な問いです: **「/api パスへのリクエストのうち、成功(200)したレスポンスの総転送量は?」**

awk 1 つでフィルターと集計を同時にできます — 条件式で行を絞り、変数に累積し、`END` ブロックで出力します。

```
awk '$7 ~ /^\/api\// && $9 == 200 {s += $10} END {print s}' /var/log/lab/access.log
```

- `$7 ~ /正規表現/` — 7 番目のフィールドが正規表現に一致するか。正規表現の中の `/` は `\/` とエスケープする。
- 変数 `s` は宣言なしで 0 から始まる。`END` ブロックはすべての行を読んだあとに 1 回実行される。

分解すると:

| 部分 | 意味 |
|---|---|
| `$7 ~ /^\/api\//` | パスのフィールドが `/api` で始まる |
| `&& $9 == 200` | かつステータスが 200 |
| `{s += $10}` | バイト数のフィールドを s に累積 |
| `END {print s}` | すべて読んだあとに合計を出力 |

課題: この合計を `~/work/api-bytes.txt` に保存して **[チェック]** してください。

```
awk '$7 ~ /^\/api\// && $9 == 200 {s += $10} END {print s}' /var/log/lab/access.log > ~/work/api-bytes.txt
```

- 前のコマンドと同じで、出力だけを `>` でファイルに保存する。
