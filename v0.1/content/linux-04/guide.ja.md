# Bash スクリプティング

1 行のコマンドを繰り返し始めたら、スクリプトにするときです。このモジュールでは **死なないスクリプトではなく、問題が起きたらすぐ死ぬ(fail-fast)スクリプト** の書き方を学びます — 黙って間違った結果を出すスクリプトこそ最も危険だからです。

作成場所はすべて `~/work/` の下です。エディターは vim/nano のどちらでもよく、`cat > ファイル <<'EOF'` のヒアドキュメントで作っても構いません。

## 安全なスクリプトの骨組み

すべてのスクリプトの最初の 2 行は事実上固定です。

```
#!/bin/bash
set -euo pipefail
```

| オプション | 効果 |
|---|---|
| `-e` | コマンドが失敗したら即座に終了 |
| `-u` | 未定義の変数を参照したらエラー(タイプミス防止) |
| `-o pipefail` | パイプの途中の段階の失敗も失敗として扱う |

課題: `~/work/sysinfo.sh` を書いてください。要件:

- bash のシバン + `set -euo pipefail`
- `host=<ホスト名>` を 1 行、`uptime=<秒>` を 1 行出力
- 実行権限

スクリプトの作成:

```
cat > ~/work/sysinfo.sh <<'EOF'
#!/bin/bash
set -euo pipefail
echo "host=$(uname -n)"
echo "uptime=$(awk '{print $1}' /proc/uptime)"
EOF
```

- `cat > ファイル <<'EOF'` … `EOF` — ヒアドキュメント。2 つの `EOF` の間の行を `cat` の入力に入れ、`>` でファイルに保存する。`'EOF'` のようにクォートすると、本文の `$(...)` が今は実行されず文字どおりに保存される。
- `#!/bin/bash` — シバン。このファイルをどのインタープリターで実行するかをカーネルに知らせる。
- `$(uname -n)` — ホスト名、`awk '{print $1}' /proc/uptime` — 起動からの経過秒数(最初のフィールド)。

実行権限の付与:

```
chmod +x ~/work/sysinfo.sh
```

- `chmod +x` — 実行(x)権限を追加する。ないと `./スクリプト` で実行したときに `Permission denied`。

実行してみる:

```
~/work/sysinfo.sh
```

- パスで直接実行すると、シバンの `/bin/bash` がスクリプトを実行する(`bash ファイル` で実行すれば実行権限がなくてもよい)。

動作を確認して **[チェック]** してください。

## 引数の処理と終了コード

スクリプトの引数は `$1 $2 …`、個数は `$#` で受け取ります。間違って呼ばれたら **usage を stderr に出力して 0 以外のコードで終了する** のが決まりです — 呼び出した側(ほかのスクリプト、CI)が失敗を検知できなければならないからです。

課題: `~/work/logcut.sh <ログファイル> <ステータスコード>` を書いてください。

- `/opt/lab/data/app.log` 形式(`… status=200 msg=…`)から、該当ステータスコードの行数を出力
- 引数が 2 つでなければ usage を出力 + 終了コード 2

スクリプトの作成:

```
cat > ~/work/logcut.sh <<'EOF'
#!/bin/bash
set -euo pipefail
usage() { echo "usage: $0 <logfile> <status>" >&2; exit 2; }
[ $# -eq 2 ] || usage
grep -c "status=$2 " "$1" || true
EOF
```

- `usage() { …; }` — 関数の定義。`>&2` はメッセージを標準エラーへ、`exit 2` は終了コード 2 で終える。
- `[ $# -eq 2 ] || usage` — 引数の数(`$#`)が 2 でなければ(`||`)usage を呼ぶ。`[ ]` は条件を検査するコマンド(`test`)。
- `grep -c "status=$2 " "$1"` — 2 番目の引数のステータスコードの行数。変数はダブルクォートで囲み、空白を含むパスでも安全に。

実行権限の付与:

```
chmod +x ~/work/logcut.sh
```

- 新しいスクリプトごとに実行権限を与える必要がある。

> `grep -c` は一致が 0 件だと **終了コード 1** を返します。`set -e` の下ではそのまま死ぬので、`|| true` で「0 件も正常」であることを明示します — fail-fast は有効にしつつ、失敗でないものを失敗として扱わない感覚が大切です。

テストしてから **[チェック]** してください。

正常な呼び出し — 500 の行数を出力:

```
~/work/logcut.sh /opt/lab/data/app.log 500
```

- 1 番目の引数が `$1`(ログファイル)、2 番目が `$2`(ステータスコード)に入る。

引数なしで呼び出し — 終了コード 2 を確認:

```
~/work/logcut.sh; echo "exit=$?"
```

- `$?` — 直前のコマンドの終了コード。`;` で続けて実行し、usage のあとのコードが 2 かを確かめる。

## trap で後片付けを保証する

一時ファイルを作るスクリプトが途中で死ぬとゴミが残ります。`trap '…' EXIT` は **正常終了でもエラーでも**、スクリプトが終わるときに必ず実行される後片付けのフックです。

課題: `~/work/withtmp.sh` を書いてください。

- `mktemp -d` で一時ディレクトリを作り、その中に何かファイルを 1 つ作る
- `trap` で終了時に一時ディレクトリを削除
- **最後の出力行** として一時ディレクトリのパスを出力(検証はこのパスが消えたかを確認します)

スクリプトの作成:

```
cat > ~/work/withtmp.sh <<'EOF'
#!/bin/bash
set -euo pipefail
tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT
date > "$tmp/scratch.txt"
echo "$tmp"
EOF
```

- `mktemp -d` — 重ならない名前の一時ディレクトリを作り、そのパスを出力する。
- `trap 'コマンド' EXIT` — スクリプトがどんな理由で終わっても、終了直前にコマンドを実行する。ここでは一時ディレクトリの削除。
- `rm -rf "$tmp"` — ディレクトリを中身ごと(`-r`)確認なしで(`-f`)消す。trap の本体はシングルクォートなので、`$tmp` は実行時に展開される。

実行権限の付与:

```
chmod +x ~/work/withtmp.sh
```

- 実行権限を付ける。

実行後に削除を確認:

```
d=$(~/work/withtmp.sh); ls -d "$d" 2>&1   # "No such file" なら正常
```

- `d=$(スクリプト)` — スクリプトの出力(一時パス)を変数 `d` に入れる。
- `ls -d "$d"` — ディレクトリそのものを参照する。`2>&1` でエラーメッセージも画面に出す。すでに消えているので `No such file` が正常。

確認したら **[チェック]** してください。

## 壊れたスクリプトの修理

最後は現実で最もよくやる仕事 — **他人が書いたスクリプトを直す** ことです。`/opt/lab/bin/backup.sh` はディレクトリを /tmp にバックアップするスクリプトですが、パスに **空白が入ると** 死にます。

スクリプトの中身を見る:

```
cat /opt/lab/bin/backup.sh
```

- 直す前にまず読む。クォートなしで使われている `$src`、`$dest` を探してみよう。

空白入りパスのテスト用ディレクトリを用意:

```
mkdir -p "/tmp/my app"; echo hi > "/tmp/my app/f.txt"
```

- パスに空白があるので、ダブルクォートで囲んで 1 つの引数として渡す。`;` で続けてテスト用ファイルも 1 つ作る。

空白入りパスで実行:

```
/opt/lab/bin/backup.sh "/tmp/my app"   # 失敗!
```

- 呼び出すときはクォートで 1 つの引数を渡したが、スクリプト内でクォートなしに `$src` を使った瞬間、また 2 つの単語に分かれる(単語分割)。

原因は **クォート(quoting)なしの変数展開** です。`$src` が `/tmp/my app` なら、`cp -r $src/*` は `/tmp/my` と `app/*` の 2 つの引数に分かれます。シェルスクリプトのバグの中でも古典中の古典です。

課題: `~/work/backup-fixed.sh` にコピーしてから直してください。

- すべての変数展開を `"…"` でクォート(`"$dest"`、`"$src"/*` — グロブの `*` はクォートの外に!)
- `set -euo pipefail` を追加
- 空白入りのパスで実行して成功を確認

コピーを作る:

```
cp /opt/lab/bin/backup.sh ~/work/backup-fixed.sh
```

- `cp <元> <先>` — 元はそのままにして、自分の作業ディレクトリにコピーを作る。

エディターで直す:

```
vim ~/work/backup-fixed.sh
```

- vim: `i` で入力モード、直したら `Esc` → `:wq` で保存・終了。慣れていなければ `nano` を使ってもよい(`Ctrl+O` 保存、`Ctrl+X` 終了)。

空白入りのパスで実行して確認:

```
~/work/backup-fixed.sh "/tmp/my app" && echo OK
```

- `A && B` — A が成功(終了コード 0)したときだけ B を実行する。`OK` が見えれば修理成功。

成功したら **[チェック]** — モジュール完了です。
